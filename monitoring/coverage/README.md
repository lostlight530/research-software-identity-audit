# Twelve-repository day/week **source coverage**, not reconstructed historical observations
This is an indexed, derived view of known GitHub public Release events and selected dated family-view evidence. Research corpus is strictly RS01–RS10; audit control and Life Science pilot are **outside** the registered sample. OSF Registration DOI `10.17605/OSF.IO/5B329` remains frozen, and `schedule/` still has no concrete offsets. This index creates **zero prospective observations**.
- [12 repository identities with creation and latest observed main SHA](repository-inventory-2026-10-24.csv). Earliest GitHub creation metadata is **2025-04-27**. Last observed main SHA shows only a checked current head, not full daily commit history.
- [45 public GitHub Release events](release-event-ledger-2026-10-24.csv) with exact API `published_at` UTC converted into `Asia/Shanghai` date. A tag's wording does not dictate publication date: Sept month close tags published at 18:xx UTC Sept30 = **Oct01** Beijing.
- [39 dates × 12 repositories = 468 daily rows](daily-repository-evidence-2026-09-16-to-2026-10-24.csv): date-specific Release events, evidence-backed source counter where available, otherwise explicit **no retained family-view source on that day**, not no traffic.
- [6 Monday-start weeks × 12 repos = 72 weekly rows](weekly-repository-evidence-2026-09-16-to-2026-10-24.csv): counts dated Release events and numeric-source-covered days, displays only the **last actual observed source value** in that week (not weekly totals or inferred change).
Coverage starts at September 16, 2026, the first fixed-ten release cohort. Dates before that back to individual GitHub repo creation are **not historically sampled** by this ledger; no retroactive full Git commit-by-day or traffic-by-day reconstruction is performed. A missing row value is **unknown/unobserved**, not 0. Only dates with a retained comparable source receive numbers; historical Oct05 baseline values appear on their **actual Oct06 ~00:33 Beijing reconciliation retrieval**, never on the Oct05 cutoff. Oct22 is a retrospective transcript of an actual earlier conversation API extraction, not a contemporaneous archived HTTP response.
Metric classes are deliberately kept separate. Older reports retain Zenodo `stats.views` attached to a record; Oct22–24 include complete family `/versions` derived `sum(version_views)` and within-response checks. Since URL variants previously returned conflicting values, **do not subtract columns as confirmed new human visits**. No imputed missing days, false CI claims, date backfilling or sample expansion. To extend, add a separate dated source record, then update this *derived index* with an explicit reference and actual retrieval clock. All original evidence/provenance paths remain unchanged.
