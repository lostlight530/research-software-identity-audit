## Zenodo: one line per software family, all versions combined
A complete `GET https://zenodo.org/api/records/{latest-id}/versions?size=25` listing for each of twelve distinct concept DOI families returned **45 version DOI records (40 fixed, 4 control, 1 pilot)**, all 12 with no additional page. In **12/12**, `sum(version_views)=attached stats.views` and `sum(version_downloads)=attached stats.downloads`. Thus the **12-row [canonical family rollup](zenodo-family-rollup.csv)** presents one total per family: fixed ten **2,545 Views**, independent control **130**, pilot **6**, 12-family descriptive total **2,681 Views / 27 Downloads**. [45-row evidence](zenodo-version-evidence.csv) preserves each individual version DOI and the eight source stats fields.

**Do not double count:** the `stats.views`, `stats.unique_views`, `stats.downloads` fields attached to different version API records are family-aggregate fields, **not an additive metric across versions**. Family `unique_views` and `unique_downloads` are copied only when the *same family-level attached field* was consistent within the returned list; never sum `version_unique_views` as unique persons, nor add family unique viewers across repositories as globally deduplicated people. This matches [Zenodo usage statistics documentation](https://zenodo.org/help/statistics), which describes family aggregation and version-specific drilldowns.

Previous individual-version URL variants returned conflicting aggregate snapshots; `/versions` gives an internally consistent **selected API representation**, not demonstrated fresh origin bytes. The rollup matches the previous morning selected-field total, but the *difference of zero* is **not proof of no new visits**. It is an observation of returned numbers only, not a growth-rate estimate.
